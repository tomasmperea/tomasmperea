## Veredicto: NO PUBLICAR — 38 / 100

El cable y el aviso están bien construidos y bien probados para el caso exacto que reportó el PM
(cambiar fechas). Pero la guarda que decide **cuándo** avisar (`CAMPOS_QUE_MUEVEN_LA_VALIJA`)
excluye `notes` con la justificación escrita "hoy no las lee nadie", y esa afirmación es **falsa**:
el motor ya lee `trip.notes` — tanto en la capa de reglas (vía `hasTrekking`/`hasWaterActivity`)
como en el prompt que se le manda al modelo — desde antes de esta entrega. Lo reproduje con el
propio motor, sin necesidad del navegador: una nota sin tocar fecha/destino/viajeros deja
`desactualizada:true, nuevos:6` en `planListUpdate`, y la guarda de VAL-63 no dispara nada para ese
caso. Es el bug original — "la lista no se entera de que cambió el viaje" — volviendo por la
puerta de "notas", que además es una puerta que el propio código ya tenía abierta.

A esto se suma que el criterio de éxito que el brief define explícitamente ("Contra el Artifact
publicado, en el teléfono del PM... un criterio que no se puede comprobar así se considera no
cumplido") no se intentó: todo lo probado es Playwright + Chromium de escritorio contra el archivo
local, sin declarar esa brecha en la entrega, y sin verificar que la v21 esté publicada.

### 6. La pregunta central: ¿la guarda deja afuera algo que mueve la valija?

Reproduje con el motor puro (`app/parts/packing-engine.js`, sin navegador):

```
node -e '
const pe = require("./app/parts/packing-engine.js");
const base = {name:"Viaje", destination:"", startDate:"2026-09-14", endDate:"2026-09-24", travelers:"Tomas"};
console.log(Object.keys(pe.buildPackingList({trip:base, items:[]}).items).length);            // 23, international=false
console.log(Object.keys(pe.buildPackingList({trip:{...base,name:"Brasil"}, items:[]}).items).length); // 28, international=true
'
```

`trip.name` alimenta `deduceInternational` (línea 1907 de `valija.html`:
`norm([trip.destination, trip.name]...)`) como respaldo cuando el destino está vacío o es ambiguo.
Con destino vacío, renombrar el viaje a un país extranjero cambia `international` de
desconocido/falso a verdadero, y eso cambia qué ítems de `BASE_RULES` aplican. **El comentario dice
"el nombre — es una etiqueta"; es falso en este caso.** (El arnés de VAL-63 no lo detecta porque su
control negativo renombra con el destino ya puesto en "Noruega", donde el destino solo ya alcanza —
no probó el caso donde el nombre es lo único que lleva la pista.)

Con `notes`, reproduje directamente el camino que usa `checkPackingPlan` (`planListUpdate`, con el
`tipoViaje` de la lista anterior fijado, tal como lo pasa `recalcularPlanContra`):

```
node -e '
const pe = require("./app/parts/packing-engine.js");
const base = {name:"Viaje", destination:"Madrid", startDate:"2026-09-14", endDate:"2026-09-24", travelers:"Tomas", notes:""};
const list0 = pe.buildPackingList({trip:base, items:[]});
const conNotas = {...base, notes:"vamos a hacer trekking y kayak"};
const upd = pe.planListUpdate({list:list0, trip:conNotas, items:[], tipoViaje:list0.tipoViaje});
console.log(upd.desactualizada, upd.nuevos.length);   // true 6
'
```

Con **sólo las notas cambiadas** (mismas fechas, mismo destino, mismos viajeros), la lista queda
`desactualizada:true` con **6 ítems nuevos** — vía la capa de `facts` (`hasTrekking`,
`hasWaterActivity`, que se evalúan sobre `textBlob`, y `textBlob` incluye `trip.notes` desde
`tripContext`, línea 2293-2296), sin necesitar IA. Y por separado, `sanitizeNotesForAI(trip.notes)`
ya se manda al prompt del modelo desde antes de esta entrega (línea 2592, usado en
`destinationPrompt` línea 2828-2833: *"Cuando el motivo venga de una reserva puntual o de las notas
del viaje, citá el dato concreto"*). **El comentario dice "las notas — hoy no las lee nadie"; es
falso**, y el brief mismo arrastra la misma idea equivocada al listar VAL-65 como lo que "convierte
las notas en entrada del motor" — ya lo son, parcialmente, desde antes.

Esto es exactamente lo que se me pidió cazar: **un campo que mueve la valija y quedó afuera de
`CAMPOS_QUE_MUEVEN_LA_VALIJA`, con una justificación escrita que no se verificó contra el código que
describe.** Con `notes` es un hecho reproducible en el propio motor; con `name` es un caso de borde
real pero menos probable (requiere destino vacío o ambiguo).
